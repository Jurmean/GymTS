# 场景接入

本文用一个 KPI 检测实验说明怎样配置、取得数据、调用方法并交付结果，再说明同一机制如何承载其它场景。

## 一次 KPI 检测实验交付什么

调用方希望回答：**选定的方法对这段服务器 CPU 数据给出了哪些异常分数，这些分数依据什么输入；如果有确认标签，检测质量如何？**

本例选择一段按分钟采样的单服务器 CPU 历史数据。任务要求每分钟用最近 60 点判断当前时点，选用 LibraryTS 中一个符合该任务协议的固定版本方法。GymTS 交付逐时点结果及可追溯的运行记录；评价报告在有明确方案和依据时另行产生。

窗口尚未形成时继续收集观测，不产生虚构的检测结果。共同窗口和单位属于任务约定；方法自己的插补、特征处理和阈值计算仍属于被测方法。

### 一份可读的实验计划

此例假定数据文件已按分钟采样，仅包含服务器 `server-7`；`cpu_pct` 的单位是百分比。适配器、任务和方法名称均为待登记的示例名称，字段格式按接口规范解释。

```yaml
protocol_version: gymts.experiment/1
name: server-cpu-detection-example
purpose: development
scene:
  environment:
    protocol_version: gymts.environment/1
    adapter: local-kpi-replay
    version: '1.0.0'
    source:
      kind: dataset
      locator: local://datasets/server-7-cpu
      revision: example-v1
      connection: {}
      credential_ref: null
    mapping:
      time: {field: timestamp, timezone: Asia/Shanghai}
      entity: {field: server_id}
      variables:
        cpu_utilization: {field: cpu_pct, dtype: float64, unit: percent}
    options: {availability: event_time}
  task:
    plugin: point_anomaly_detection
    version: '1.0.0'
    params:
      variables: [cpu]
      sample_period: 1min
      window_points: 60
      decision_every: 1min
      missing: preserve_mask
      output: point_anomaly_score
  binding:
    variables:
      cpu:
        source: cpu_utilization
        unit: ratio
        transform: {name: divide_by_100, version: '1.0.0', origin_ref: null}
    operations: {}
candidate:
  adapter: library-window-detector
  version: '1.0.0'
  artifact: null
  params: {}
  inherited_state: []
execution:
  mode: stream
  start: {mode: reinitialize}
  scope:
    start: '2026-09-01T08:00:00+08:00'
    end: '2026-09-01T10:00:00+08:00'
  feedback_until: null
  seed: null
  learning:
    prepare: load_only
    online: frozen
    training_view: null
    training_targets: null
    alignment_schema_ref: null
    allowed_feedback_sources: []
  limits:
    max_inputs: null
    max_operations: null
    max_turns_per_case: 32
    max_wall_time_s: 60
recording:
  store_ref: local://records/default
  inputs: reference
  outputs: full
  artifacts: reference
  model_calls: none
  on_capture_failure: fail_run
  redaction_policy_ref: null
  extra_event_kinds: []
extensions: {}
```

`candidate` 是配置中选方法的位置，对应 EnvironmentTS 内部的一个可调用实例。上例无模型文件，因此 `artifact=null`；算法实现版本由已登记的适配声明确定。

调用方得到 RunResult，其中 status 表示执行终态，completion 表示停止原因；result_ref、trace_ref 和 artifact_refs 使用固定 ArtifactRef。完整字段以[接口规范第 9 节](../GymTS接口规范/GymTS接口规范.md#94-runresult-与-runrecord)为准，不能将可变文件路径当作证据引用。

`result_ref` 中的每项检测结果关联服务器、变量、目标时点、原始输出和输入窗口。调用方可以据此查看某个分数的依据。没有标签时依然能够完成这次运行；正确率等需要标签的指标则不能据此直接给出。独立评分使用 `AutoBenchTS.score`，重新执行测试案例使用 `AutoBenchTS.evaluate`。

## 更换来源或方法时，具体改哪里

实时源若没有预热历史，就先积累本次会话的窗口；不能因为历史实验一开始已有上下文，就假定实时实验也具备。同一接口保证使用方式与含义清楚，不保证不同来源的数据分布或测试难度相同。

## 五种实践如何映射到同一过程

下面各场景都复用“取得观测 → 构造任务输入 → 运行方法 → 处理输出/请求 → 记录及评价”。变化集中在来源能力、任务含义和评价依据。

**ChatTS 合成快照**

生成器先固定版本、参数和 seed，产出不可变时序快照；Environment 按 dataset 能力接入。合成标签作为独立 OutcomeView，是否可用于训练由用途策略明确。若 Candidate 使用原生时序张量，采集还需保存实际张量和编码/预处理版本。

**阿里 CMS 只读观测**

Environment 使用 live/attach，声明 external 推进、可查变量、查询时间限制和无操作能力。数据保留事件时间与实际 available_at；每次交付保存实际快照。finish 仅脱离本次连接，不停止现场服务。连接器、权限和字段映射需按实际平台适配。

**原生 Gym 控制环境**

Environment 声明 transition/on_action：reset 缓存初态，observe 消费，act 执行一次 step，下一 observe 只交付缓存转移。操作意图、回执、后态和最后奖励分别记录；terminated/truncated 均保留。未消费转移前不允许再次 act。

**诊断 Agent 查询**

Agent 通过 Candidate 接入，窗口查询输出经 Task 解释为 query，再由 Runner 执行。查询保持同 case，下一 TaskInput 的 turn_id 递增；内部模型/工具调用通过采集适配器关联 input_id/output_id。新的环境读取不能绕过 Task/Runner。

**预测与延迟结果**

Task 固定预测发出时点、目标时点、步长和实体/变量匹配键；execution.scope 按发出时点约束。未来实际值以新 OutcomeRecord 在到达后关联，缺失时不填零。AutoBenchTS.score 使用固定依据快照重评分，原预测和旧报告保持。

这组实践中的区别有直接设计含义：快照可以重读，但不会响应新控制；实时系统自行运行，结束观测不等于关闭系统；控制环境的动作会改变后续状态；查询只补充已允许的信息；预测的评价依据可能晚于运行输出。

## LibraryTS 各类条目

让库里的算法都能参与 GymTS，需要为不同用途提供相应接法。并非每个函数都应包装成一个独立决策者。

例如 RL 训练器可以调用 GymTS 收集一段有边界的交互，再通过记录接口取得允许的状态、动作、奖励、后态和结束信息，完成原生更新并保存新策略版本。下一 Run 明确使用该版本；独立评价另按固定方案进行。需要保留并行环境或特殊调度的算法，应在实际接入时适配其训练流程。

进入实现时，一项场景接入交付三件东西即可说清：**实际来源和取数映射、任务与方法的匹配配置、一份能追溯输入与输出的示例运行。** LibraryTS 的真实条目还需逐项完成适配；本页给出的是接入路径。
