# 路线图与框架演进

路线图表达接入和验证方向，不承诺发布日期、负责人或已获资源。当前可用范围见
[项目状态](project-status.md)，企业平台完整方案见[历史路线评审](enterprise-platform-roadmap.md)。

## 持续原则

1. 接入真实项目，先保留其原生语义，通过独立适配器暴露公开合同。
2. EnvironmentTS 守住执行/证据，AutoBenchTS 守住评价；项目格式、模型和领域评分留在外部。
3. 每次核心变化记录未满足需求、适配器无法解决的原因、兼容方式及旧项目回归。
4. 定期冻结核心，让新项目完成运行、封存、独立评价和同 Run 重评；以真实兼容性判断通用性。
5. 能复用已有训练、Agent、仿真与运维基础设施时，优先通过适配复用。

## 后续方向与验收条件

| 方向 | 增量范围 | 完成证据 |
| --- | --- | --- |
| 独立接入持续验证 | 新数据源、新 Task、方法与 Scorer，不增加项目名称分支 | 固定核心上的实际运行、非法组合拒绝、独立安装/移除和原 Run 重评 |
| Agent 工具工作流 | 保留 Agent 原生循环，连接多种可替换工具提供方 | 真实选择工具→调用→消费结果→继续推理；环境读写权限、成本、失败和全部调用有证据 |
| 资源协作与共享 | 远程资源索引、审核发布、大规模读取、更多领域投射 | 不可变身份、用途授权、并发发布与跨机器重放；仍由外部格式/领域适配处理 |
| Runtime 边界 | 外置 worker、隔离、强制中断、取消、恢复和资源治理 | 不可信插件与资源耗尽负例、失败恢复、完整证据和真实多团队试点 |
| 训练后端与 profile | 在实际需求下复用更多后端和多轮导出 | 固定快照、完整 mask/reward 血缘、真实更新、检查点新进程加载与独立评价 |
| 生产 live testbed | 按目标系统接入认证、部署身份与允许的操作 | 只读/写权限分别验收，未知副作用不重发，附着资源不被误关闭 |

## 如何提出变化

先提交具体工作流或最小失败案例，写明当前哪个接口无法表达。若只涉及新的字段格式、
算法、codec 或评分规则，优先新建/更新独立适配包。核心变更需要合同版本和迁移方案；
草案字段不能直接作为已实现 API 对外宣传。使用 [贡献指南](../CONTRIBUTING.md)和
[适配开发](adapter-development.md)中的检查流程。
